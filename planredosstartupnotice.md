# План проекта: механизм информирования пользователя при старте (РЕД ОС)

**Статус на момент выгрузки:** окно переработано в карточку «ежедневного
брифинга» (фон-фото, приветствие, задачи, фраза дня), таймер блокировки
и заголовок «Задачи» перенесены из текстовой колонки на весь экран,
кнопка «Вперёд!» — по центру внизу экрана. Время блокировки теперь по
умолчанию считается автоматически по числу задач (5 сек/задачу), а не
задаётся фиксированным числом. Список задач вмещает до 15 пунктов.
Приветствие показывает имя и отчество пользователя из домена (AD/GECOS),
без фамилии. Текущая версия пакета — **1.0.0-12**, все изменения собраны,
установлены и визуально проверены на тестовой ВМ, закоммичены и
запушены в `claude/startup-notification-mechanism-tdgen6`.

Репозиторий: `romprs/data3`, ветка `claude/startup-notification-mechanism-tdgen6`.

## ⚠️ Важно: LF-концы строк при сборке с Windows

При сборке `git archive` **с этой Windows-машины** (`core.autocrlf =
true`) исходники экспортировались с CRLF-концами строк, хотя в самом
репозитории (blob) они хранятся с LF. Это ломало шебанг скрипта
`bin/startup-notice` (`#!/usr/bin/sh\r`) — systemd не мог его выполнить:
`Failed to execute /usr/bin/startup-notice: No such file or directory`
(EXEC 203). Раньше пакеты собирались на Linux/из GitHub — там проблема
не проявлялась. Исправлено добавлением `.gitattributes` с
`* text=auto eol=lf`, форсирующим LF при экспорте независимо от
локальных настроек git. **При сборке архива всегда проверять**:
```sh
tar xOzf redos-startup-notice-1.0.0.tar.gz redos-startup-notice-1.0.0/bin/startup-notice | file -
```
— не должно быть "with CRLF line terminators".

## 1. Задача

После авторизации пользователя в РЕД ОС на экран должно выводиться окно с
настраиваемым сообщением. Окно нельзя закрыть, свернуть или переключиться на
другое приложение в течение настраиваемого времени. По истечении этого
времени в окне появляется кнопка закрытия. Сценарий применения —
организационное информирование (регламенты, уведомления безопасности и
т.п.), поэтому блокировка должна быть надёжной, а не просто визуальной
подсказкой.

## 2. Целевое окружение

| Параметр | Значение |
|---|---|
| ОС | РЕД ОС |
| Окружения рабочего стола | MATE, KDE Plasma, GNOME (решение DE-агностичное) |
| Графический сервер | X11 (обязательное условие — см. п. 3) |
| Стек реализации | Python 3 + GTK3 (PyGObject) |
| Поставка | RPM-пакет, автозапуск через XDG autostart + systemd user unit |

**Почему X11, а не Wayland:** надёжная блокировка Alt+Tab и переключения
окон программно возможна только через X11 grab API. Под Wayland композитор
по соображениям безопасности не выдаёт приложениям таких полномочий —
на нём эквивалентный по надёжности механизм технически недостижим.

## 3. Архитектура решения

### 3.1. Приложение `startup-notice`

```
README.md
.gitattributes                      — форсирует LF при git archive
packaging/
  redos-startup-notice.spec       — RPM-спека
src/startup_notice/
  __init__.py
  __main__.py                     — точка входа
  config.py                       — чтение/валидация конфига
  lockwindow.py                   — окно + логика блокировки
  log.py                          — логирование в journal/syslog
data/
  startup-notice.desktop          — XDG autostart entry
  startup-notice.service          — systemd --user unit
  config.ini.example
  tasks.txt.example, phrases.txt.example
  backgrounds/                    — 5 готовых фото + SOURCES.md
bin/startup-notice                — shell-обёртка (python3 -m startup_notice)
tests/
  test_config.py                  — 18 unit-тестов, покрывают config.py
```

**Логика окна (`lockwindow.py`):**
- `Gtk.Window` без декораций, fullscreen, `keep_above`, `stick`,
  скрыт из панели задач/переключателя окон.
- **Блокировка переключения** — ключевой механизм: X11 keyboard+pointer
  grab через `Gdk.Seat.grab()`. Тот же приём, что используют экранные
  блокировщики (i3lock, light-locker). Пока grab активен, Alt+Tab, Super,
  клики по панели задач не доходят до других приложений. WM-хинты сами по
  себе ненадёжны (MATE/KDE/GNOME чтут их по-разному), поэтому основа —
  именно grab, а не хинты.
- Watchdog раз в секунду: если grab случайно потерян — повторный захват.
- Время блокировки по умолчанию **вычисляется по числу задач** (см. п.
  «Конфигурация» ниже); явно заданный в конфиге `lock_duration_seconds`
  полностью переопределяет расчёт, включая полное отключение показа окна
  при значении 0 — это отдельный флаг `Config.disabled`, который
  срабатывает только при явном значении администратора, а не при
  автоматически вычисленном нуле (нет задач → окно всё равно
  показывается, просто сразу разблокированным).

**Внешний вид (по образцу присланного макета "ежедневного брифинга"):**
- Фон — случайно выбранное изображение из каталога `background_dir`,
  отрисовывается через `cairo` с масштабированием "cover" (заполняет
  экран, сохраняя пропорции, без искажений) плюс тёмный градиент слева
  направо поверх фото для читаемости текста, подобранный под тон
  конкретного фото (усреднение цвета + затемнение).
- Шапка: дата и день недели (генерируются автоматически, RU) слева;
  обратный отсчёт до разблокировки — компактным бейджем в правом верхнем
  углу.
- Приветствие: аватар-кружок с первой буквой имени + текст
  «Добрый день/вечер/утро/ночи, <Имя Отчество>» — время суток вычисляется
  автоматически; имя и отчество берутся из GECOS системной учётной записи
  (`pwd.getpwnam`), которая в корпоративных доменах заполняется в русском
  порядке «Фамилия Имя Отчество» — используются второе и третье слово,
  без фамилии. Если отчества нет — только имя; если GECOS вовсе не задан —
  системный логин.
- Блок **«Задачи: N»** (без значка, двоеточие перед числом) — список из
  `tasks_file`, до 15 пунктов (было 5); при пустом/отсутствующем файле
  блок не показывается вовсе.
- «Мысль дня» — случайная строка из `phrases_file`, приподнята над низом
  окна отступом.
- Кнопка **«Вперёд!»** — по центру по горизонтали, у нижнего края экрана
  (не строго по центру экрана); появляется только после истечения
  времени блокировки и завершает работу приложения.

**Конфигурация** (`/etc/startup-notice/config.ini`):
```ini
[message]
tasks_file = /etc/startup-notice/tasks.txt
phrases_file = /etc/startup-notice/phrases.txt

[appearance]
background_dir = /etc/startup-notice/backgrounds
font_size = 16

[behavior]
seconds_per_task = 5
;lock_duration_seconds = 30
```
- `tasks_file`/`phrases_file`/`background_dir` — если ключ **отсутствует
  в конфиге вовсе** (например, старый config.ini от версии до 1.0.0-5,
  сохранённый при обновлении пакета как `%config(noreplace)`) —
  используется файл/каталог по умолчанию рядом с config.ini, который
  реально ставит пакет (`tasks.txt`/`phrases.txt`/`backgrounds`). Если
  значение **явно оставлено пустым** — администратор осознанно отключил
  блок, и он не показывается. Это разграничение (отсутствует vs. пусто)
  специально появилось в 1.0.0-10, чтобы обновление пакета не «съедало»
  примеры фото/фраз у тех, кто ставил ещё версию 1.0.0-4.
- `seconds_per_task` — сколько секунд блокировки на одну задачу;
  итоговое время = `seconds_per_task * количество задач`. Действует,
  только если `lock_duration_seconds` ниже не задан явно.
- `lock_duration_seconds` — если раскомментировать, полностью заменяет
  расчёт по числу задач фиксированным значением; 0 — полностью отключает
  показ окна (сервис завершается сразу, без вывода).

Примеры: `data/config.ini.example`, `data/tasks.txt.example`,
`data/phrases.txt.example`.

### 3.2. Автозапуск после входа пользователя

- `/etc/xdg/autostart/startup-notice.desktop` — freedesktop autostart entry,
  подхватывается одинаково MATE, KDE Plasma и GNOME.
  `Exec=systemctl --user start startup-notice.service` (не `enable`, чтобы
  не зависеть от per-user enablement и не ловить гонку на старте сессии).
- `/usr/lib/systemd/user/startup-notice.service` — фактический запуск
  приложения; даёт журналирование (`journalctl --user -u startup-notice`)
  и гарантирует единственный инстанс на пользовательскую сессию.

### 3.3. RPM-пакет

`packaging/redos-startup-notice.spec`, `BuildArch: noarch`.
- Зависимости: `python3-gobject`, `python3-cairo` (нужна для отрисовки
  фонового изображения), `gtk3`, `systemd`.
- Устанавливает: `/usr/bin/startup-notice`,
  `%{python3_sitelib}/startup_notice/`,
  `/etc/xdg/autostart/startup-notice.desktop`,
  `/usr/lib/systemd/user/startup-notice.service`,
  `/etc/startup-notice/config.ini`, `tasks.txt`, `phrases.txt`
  (все три — `%config(noreplace)`, обновление пакета не затирает
  настройки администратора), `/etc/startup-notice/backgrounds/*.jpg`.

## 4. Сборка и установка

```sh
sudo dnf install -y rpm-build rpmdevtools git python3-devel python3-gobject gtk3
rpmdev-setuptree

git clone https://github.com/romprs/data3.git
cd data3 && git checkout claude/startup-notification-mechanism-tdgen6

VERSION=1.0.0
git archive --prefix=redos-startup-notice-$VERSION/ \
    -o ~/rpmbuild/SOURCES/redos-startup-notice-$VERSION.tar.gz HEAD

# проверить, что шебанг не сломан CRLF (см. раздел выше)
tar xOzf ~/rpmbuild/SOURCES/redos-startup-notice-$VERSION.tar.gz \
    redos-startup-notice-$VERSION/bin/startup-notice | file -

cp packaging/redos-startup-notice.spec ~/rpmbuild/SPECS/
rpmbuild -ba ~/rpmbuild/SPECS/redos-startup-notice.spec

sudo dnf install ~/rpmbuild/RPMS/noarch/redos-startup-notice-*.rpm
```

Для распространения на несколько машин — локальный dnf-репозиторий:
```sh
sudo dnf install -y createrepo_c
mkdir -p /srv/local-repo
cp ~/rpmbuild/RPMS/noarch/redos-startup-notice-*.rpm /srv/local-repo/
createrepo_c /srv/local-repo
```
