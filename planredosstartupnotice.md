# План проекта: механизм информирования пользователя при старте (РЕД ОС)

**Статус на момент выгрузки:** переработан внешний вид окна (карточка с
фоновым изображением, персональным приветствием, задачами и фразой дня —
по образцу присланного макета), проверено сборкой и живым прогоном на
тестовой РЕД ОС ВМ (1.0.0-5). По итогам просмотра внесены доработки
раскладки (1.0.0-6): кнопка «Вперёд!» и таймер вынесены из текстовой
колонки на весь экран, укрупнён шрифт задач, градиент под фото стал
адаптивным по цвету, добавлены 5 готовых фоновых фотографий. Текущая
версия пакета — **1.0.0-7** (в 1.0.0-7 донагелировано: тема окружения
переопределяла цвет надписи на кнопке «Вперёд!» через `button label` —
добавлен явный CSS-селектор `.proceed-button label`, обнаружено и
проверено визуально на тестовой ВМ).

Репозиторий: `romprs/data3`, ветка `claude/startup-notification-mechanism-tdgen6`.

---

## 1. Задача

После авторизации пользователя в РЕД ОС на экран должно выводиться окно с
настраиваемым сообщением. Окно нельзя закрыть, свернуть или переключиться на
другое приложение в течение настраиваемого времени. По истечении этого
времени в окне появляется кнопка закрытия. Сценарий применения —
организационное информирование (регламенты, уведомления безопасности и
т.п.), поэтому блокировка должна быть надёжной, а не просто визуальной
подсказкой.

## 2. Целевое окружение

| Параметр | Значение |
|---|---|
| ОС | РЕД ОС |
| Окружения рабочего стола | MATE, KDE Plasma, GNOME (решение DE-агностичное) |
| Графический сервер | X11 (обязательное условие — см. п. 3) |
| Стек реализации | Python 3 + GTK3 (PyGObject) |
| Поставка | RPM-пакет, автозапуск через XDG autostart + systemd user unit |

**Почему X11, а не Wayland:** надёжная блокировка Alt+Tab и переключения
окон программно возможна только через X11 grab API. Под Wayland композитор
по соображениям безопасности не выдаёт приложениям таких полномочий —
на нём эквивалентный по надёжности механизм технически недостижим.

## 3. Архитектура решения

### 3.1. Приложение `startup-notice`

```
README.md
packaging/
  redos-startup-notice.spec       — RPM-спека
src/startup_notice/
  __init__.py
  __main__.py                     — точка входа
  config.py                       — чтение/валидация конфига
  lockwindow.py                   — окно + логика блокировки
  log.py                          — логирование в journal/syslog
data/
  startup-notice.desktop          — XDG autostart entry
  startup-notice.service          — systemd --user unit
  config.ini.example
bin/startup-notice                — shell-обёртка (python3 -m startup_notice)
tests/
  test_config.py                  — 6 unit-тестов, покрывают config.py
```

**Логика окна (`lockwindow.py`):**
- `Gtk.Window` без декораций, fullscreen, `keep_above`, `stick`,
  скрыт из панели задач/переключателя окон.
- **Блокировка переключения** — ключевой механизм: X11 keyboard+pointer
  grab через `Gdk.Seat.grab()`. Тот же приём, что используют экранные
  блокировщики (i3lock, light-locker). Пока grab активен, Alt+Tab, Super,
  клики по панели задач не доходят до других приложений. WM-хинты сами по
  себе ненадёжны (MATE/KDE/GNOME чтут их по-разному), поэтому основа —
  именно grab, а не хинты.
- Watchdog раз в секунду: если grab случайно потерян — повторный захват.
- `lock_duration_seconds = 0` — специальное значение: показ окна отключён
  полностью (сервис запускается и сразу штатно завершается). Удобно, чтобы
  временно выключить уведомление, не удаляя пакет и не трогая автозапуск.

**Внешний вид (по образцу присланного макета "ежедневного брифинга"):**
- Фон — случайно выбранное изображение из каталога `background_dir`,
  отрисовывается через `cairo` с масштабированием "cover" (заполняет
  экран, сохраняя пропорции, без искажений) плюс тёмный градиент слева
  направо поверх фото для читаемости текста.
- Шапка: дата и день недели (генерируются автоматически, RU) слева;
  обратный отсчёт до разблокировки — компактным бейджем в правом верхнем
  углу (раньше был крупной строкой по центру).
- Приветствие: аватар-кружок с первой буквой имени + текст
  «Добрый день/вечер/утро/ночи, <Имя>» — время суток вычисляется
  автоматически, имя берётся из GECOS системной учётной записи
  (`pwd.getpwnam`), с fallback на логин, если полное имя не задано.
- Блок «Задачи N» — список из `tasks_file` (по строке на задачу); при
  пустом/отсутствующем файле блок не показывается вовсе.
- «Мысль дня» — случайная строка из `phrases_file`.
- Кнопка **«Вперёд!»** (аналог прежней «Закрыть») появляется только после
  истечения времени блокировки и завершает работу приложения.

**Конфигурация** (`/etc/startup-notice/config.ini`):
```ini
[message]
tasks_file = /etc/startup-notice/tasks.txt
phrases_file = /etc/startup-notice/phrases.txt

[appearance]
background_dir = /etc/startup-notice/backgrounds
font_size = 16

[behavior]
lock_duration_seconds = 30
```
`tasks_file`/`phrases_file` — списки, по одному пункту на строку; могут
перегенерироваться внешним скриптом (например, результатом запроса к
базе данных — сейчас это файл, в перспективе можно брать напрямую из
БД). `background_dir` — каталог с `.jpg/.jpeg/.png`; каждый показ окна
выбирает случайный файл. При отсутствии/повреждении конфига или любого
из файлов приложение не падает — использует безопасные значения по
умолчанию, а ошибку пишет в журнал. Так уведомление не «теряется» из-за
опечатки администратора.

Примеры: `data/config.ini.example`, `data/tasks.txt.example`,
`data/phrases.txt.example`.

### 3.2. Автозапуск после входа пользователя

- `/etc/xdg/autostart/startup-notice.desktop` — freedesktop autostart entry,
  подхватывается одинаково MATE, KDE Plasma и GNOME.
  `Exec=systemctl --user start startup-notice.service` (не `enable`, чтобы
  не зависеть от per-user enablement и не ловить гонку на старте сессии).
- `/usr/lib/systemd/user/startup-notice.service` — фактический запуск
  приложения; даёт журналирование (`journalctl --user -u startup-notice`)
  и гарантирует единственный инстанс на пользовательскую сессию.

### 3.3. RPM-пакет

`packaging/redos-startup-notice.spec`, `BuildArch: noarch`.
- Зависимости: `python3-gobject`, `python3-cairo` (нужна для отрисовки
  фонового изображения), `gtk3`, `systemd`.
- Устанавливает: `/usr/bin/startup-notice`,
  `%{python3_sitelib}/startup_notice/`,
  `/etc/xdg/autostart/startup-notice.desktop`,
  `/usr/lib/systemd/user/startup-notice.service`,
  `/etc/startup-notice/config.ini` (`%config(noreplace)` — обновление
  пакета не затирает настройки администратора).

## 4. Сборка и установка

```sh
sudo dnf install -y rpm-build rpmdevtools git python3-devel python3-gobject gtk3
rpmdev-setuptree

git clone https://github.com/romprs/data3.git
cd data3 && git checkout claude/startup-notification-mechanism-tdgen6

VERSION=1.0.0
git archive --prefix=redos-startup-notice-$VERSION/ \
    -o ~/rpmbuild/SOURCES/redos-startup-notice-$VERSION.tar.gz HEAD

cp packaging/redos-startup-notice.spec ~/rpmbuild/SPECS/
rpmbuild -ba ~/rpmbuild/SPECS/redos-startup-notice.spec

sudo dnf install ~/rpmbuild/RPMS/noarch/redos-startup-notice-*.rpm
```

Для распространения на несколько машин — локальный dnf-репозиторий:
```sh
sudo dnf install -y createrepo_c
mkdir -p /srv/local-repo
cp ~/rpmbuild/RPMS/noarch/redos-startup-notice-*.rpm /srv/local-repo/
createrepo_c /srv/local-repo
```

   как раньше.
1. **Запуск без перелогина** — `systemctl --user start startup-notice.service`;
   при проблемах — `journalctl --user -u startup-notice -e`.
2. **Проверка блокировки** — пока не истёк `lock_duration_seconds`: Alt+Tab,
   клики по панели задач, Alt+F4/крестик не должны иметь эффекта; после

3. **Настройка сообщения** — `/etc/startup-notice/config.ini`, применяется
   при следующем запуске окна.
4. **Проверка настоящего автозапуска** — разлогин/логин или перезагрузка:
   окно должно появляться само.
