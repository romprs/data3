# redos-startup-notice

Механизм информирования пользователя при старте компьютера (РЕД ОС).

После входа пользователя в графическую сессию (MATE, KDE Plasma, GNOME — X11)
на экране появляется модальное окно с сообщением, текст и время блокировки
которого настраиваются в конфигурационном файле. В окне отображается
обратный отсчёт времени до разблокировки. Пока не истекло настроенное время,
окно нельзя закрыть, свернуть или переключиться на другое приложение. После
истечения времени в окне появляется кнопка закрытия.

## Требования

- РЕД ОС (или другой RPM-дистрибутив на базе systemd), графическая сессия X11.
- Пакеты: `python3-gobject`, `python3-cairo`, `gtk3`, `systemd`.

## Структура проекта

```
packaging/redos-startup-notice.spec  - RPM-спека
src/startup_notice/                  - исходный код приложения (Python3 + PyGObject/GTK3)
data/startup-notice.desktop          - XDG autostart entry (/etc/xdg/autostart)
data/startup-notice.service          - systemd --user unit
data/config.ini.example              - пример конфигурации
tests/                                - модульные тесты
```

## Сборка и установка

```sh
# 1. Собрать источники в tar.gz с ожидаемым spec'ом именем каталога
VERSION=1.0.0
git archive --prefix=redos-startup-notice-$VERSION/ -o \
    ~/rpmbuild/SOURCES/redos-startup-notice-$VERSION.tar.gz HEAD

# 2. Собрать RPM
rpmbuild -ba packaging/redos-startup-notice.spec

# 3. Установить
sudo dnf install ~/rpmbuild/RPMS/noarch/redos-startup-notice-*.rpm
```

Пакет устанавливает:
- `/usr/libexec/startup-notice/` — код приложения;
- `/usr/bin/startup-notice` — точка входа;
- `/etc/xdg/autostart/startup-notice.desktop` — автозапуск при входе пользователя
  (работает единообразно на MATE/KDE Plasma/GNOME);
- `/usr/lib/systemd/user/startup-notice.service` — юнит, который фактически
  запускает приложение (даёт журналирование и единственный инстанс на сессию);
- `/etc/startup-notice/config.ini` — конфигурация (`%config(noreplace)`,
  обновление пакета не затирает изменения администратора).

Запуск после логина устроен так: XDG autostart entry делает
`systemctl --user start startup-notice.service`, а не `enable`, чтобы не зависеть
от состояния per-user enablement и не создавать гонку на старте сессии.

## Внешний вид окна

Окно показывает: дату и день недели, обратный отсчёт (отдельным бейджем в
правом верхнем углу экрана), персональное приветствие (по времени суток +
имени и отчества пользователя из учётной записи ОС — GECOS в формате
«Фамилия Имя Отчество», в приветствии используются второе и третье слова,
без фамилии), список задач «Задачи: N» (до 15 штук) из файла, случайную
фразу дня и, после истечения времени блокировки, кнопку «Вперёд!» по
центру внизу экрана. Фоном служит случайно выбранное изображение из
настроенного каталога — масштабируется под экран с сохранением пропорций
(cover-fit), а тёмный градиент слева направо (для читаемости текста)
подбирается под тон конкретного фото, а не фиксированного цвета. В
комплекте есть 5 готовых фотографий (`data/backgrounds/`, источники и
лицензия — в `data/backgrounds/SOURCES.md`), их можно заменить своими.

## Конфигурация

`/etc/startup-notice/config.ini`:

```ini
[message]
tasks_file = /etc/startup-notice/tasks.txt
phrases_file = /etc/startup-notice/phrases.txt

[appearance]
background_dir = /etc/startup-notice/backgrounds
font_size = 16

[behavior]
seconds_per_task = 5
;lock_duration_seconds = 30
```

- `tasks_file` — список задач, по одной на строку. Файл может
  перегенерироваться внешним скриптом (например, результатом запроса к
  базе данных). Если оставить значение пустым — блок «Задачи» в окне не
  показывается. Если ключ вовсе отсутствует в конфиге (например, старый
  `config.ini` от версии до 1.0.0-5, сохранённый при обновлении пакета как
  `%config(noreplace)`) — используется `tasks.txt` рядом с `config.ini`,
  который ставит сам пакет.
- `phrases_file` — фразы дня, по одной на строку; при каждом показе окна
  случайно выбирается одна. Пустое значение отключает блок; отсутствующий
  ключ — как и для `tasks_file` — берёт `phrases.txt`, поставленный
  пакетом. Если в итоге файла нет или он пуст, показывается подсказка
  администратору настроить его.
- `background_dir` — каталог с изображениями (`.jpg`/`.jpeg`/`.png`); при
  каждом показе окна случайно выбирается одно. Пустое значение отключает
  фон; отсутствующий ключ берёт каталог `backgrounds`, поставленный
  пакетом. Если каталог в итоге не найден или пуст — используется тёмный
  фон без изображения.
- `seconds_per_task` — сколько секунд блокировки приходится на одну
  задачу из `tasks_file`. Итоговое время блокировки = `seconds_per_task
  * количество задач`; нет задач — окно сразу разблокировано (без периода
  ожидания, но само окно по-прежнему показывается). Действует, только
  пока `lock_duration_seconds` не задан.
- `lock_duration_seconds` — фиксированное время блокировки в секундах;
  если задать явно (в т.ч. закомментированную по умолчанию строку в
  примере), полностью заменяет собой расчёт по числу задач.

Примеры файлов: `data/config.ini.example`, `data/tasks.txt.example`,
`data/phrases.txt.example`.

Если конфиг отсутствует или повреждён, приложение всё равно показывает
окно — с безопасными значениями по умолчанию, а ошибка парсинга пишется в
журнал. Так организационное уведомление не «теряется» из-за опечатки в
конфиге.

Явно заданное `lock_duration_seconds = 0` полностью отключает показ окна —
сервис запускается и сразу штатно завершается, ничего не выводя на экран.
Это способ временно выключить уведомление, не удаляя пакет и не трогая
автозапуск. Обратите внимание: это не то же самое, что автоматически
вычисленные 0 секунд при пустом списке задач — в этом случае окно
по-прежнему показывается (с приветствием, фразой дня и фоном), просто
сразу разблокированным.

## Логи

```sh
journalctl --user -u startup-notice
```

## Как устроена блокировка переключения

WM-хинты (`keep_above`, `skip_taskbar` и т.п.) по-разному соблюдаются разными
DE и сами по себе не гарантируют блокировку. Поэтому вдобавок к ним окно
захватывает клавиатуру и указатель на уровне X11 (`Gdk.Seat.grab`) — тот же
приём, которым пользуются экранные блокировщики (i3lock, light-locker). Пока
захват активен, Alt+Tab, Super, клики по панели задач и другим окнам не
доходят до остальной системы. Это и есть причина, по которой решение годится
только для X11: под Wayland композитор не выдаёт приложениям такие
полномочия по соображениям безопасности.
